# book 写作规范

> 本文件管页型、模板与示例写法。内容归属、链接方向、文档同步与当前状态规则统一见
> [doc-system.md](doc-system.md)；延后项格式见 [philosophy.md](philosophy.md#延后特性管理必须遵守)，
> 手册规划见 [learn/OUTLINE.md](../../learn/OUTLINE.md)。

## 第一部分：reference / internals

### 页型与页头

| 页型 | 内容 | 位置 |
|---|---|---|
| 概览页 | 子系统范围与导航 | 各书首页 / 分区 README |
| 参考页 | 可独立查询的规则、参数与示例 | reference |
| 机制页 | 设计理由、运作方式、实现位置 | internals |

一页一个主题，内容跨受众时拆页；learn 使用下文的章节写法。
H1 下用引用块给检索入口：

```markdown
# 垃圾回收（GC）

> 代码：`src/runtime/src/gc/`
> 相关：[执行模型](execution-model.md)
```

- **代码**：权威目录或文件，纯概念页可省。
- **相关**：可选，链接强相关页面。
- **待办**：可选，已知缺口的一行摘要；与限制 / Deferred 的分工见 doc-system，不把省略误解为已经验证完整。
- **状态**：只用于未实施设计，如「设计已定 / 未实施」；已完成事项不标历史状态，也不加核对日期。

### 机制页骨架

出现的节使用以下名称和顺序，不适用的整节省略，保持锚点稳定：

```markdown
## 概述
[是什么、解决什么问题，1–3 句]

## 设计目标与约束
[目标与边界]

## 方案与决策
[有实质取舍时比较选项，说明选择理由]

## 机制
[流程、状态与关系；语法机制页按需细分语法 / 语义 / 脱糖]

## 实现
[算法、关键不变量；用「组件 / 代码位置」表定位]

## 边界与限制
[当前不支持项与已知问题]

## Deferred
[按 philosophy 的格式登记具体延后项]
```

IR 指令与二进制格式规格归 internals；指令条目包含名称、操作数、语义与伪代码，不另写进 reference。

### 参考页骨架

```markdown
## 概述
[主题与查询范围]

## 约定
[编码、命名、单位等读表须知]

## <条目>
[名称、语义、参数与示例]
```

标准库 API 页由源码文档注释生成；维护方式见 doc-system 三问。

### 图表与代码

| 内容 | 形式 |
|---|---|
| 流程、状态、时序、分层 | Mermaid，并配文字结论 |
| 对比、枚举、映射 | Markdown 表格 |
| 字节或内存布局 | ASCII 定宽块 |
| 代码行为 | 对应语言代码块 |

z42 代码使用 `z42` 标注，IR / 输出用对应格式或 `text`。行为变化时同步示例，保证可解析 / 可运行。
只在有助理解时加图，不为凑结构画图。

### 简洁与检索

- 文件名用 kebab-case，H1 唯一；每节先给结论，页长软限约 400 行，超长时拆页并挂入 SUMMARY。
- 代码引用用路径与符号，不写行号；用通行术语，关键术语保留英文。
- 写代码读不出的机制与理由，不逐句复述实现；入口用法与文件清单链接目录 README，完整操作配方可归 internals。
- 链接格式与历史叙事的边界统一按 doc-system 执行。

## 第二部分：learn 学习手册与 examples

### 章节与读者

- 一章一页，路径 `docs/learn/src/<part>/<chapter>.md`；写完才挂入 SUMMARY，未写章节只留 OUTLINE。
- 开头说明本章要做什么，结尾列小结，需要时给下一步。首次术语加粗并解释；与 C# 不同的地方用引用块说明。
- 只讲学习本章所需的规则，完整契约链接 reference；不展开编译器或 VM 实现，链接方向按 doc-system。
- 通用阅读约定只写在 `getting-started/how-to-read.md`，各章不重复「代码在哪、输出怎么读」等通用说明。
  具体片段仍须说明所属文件与运行方式。

### 示例出处与输出

两种出处写法：

1. 手把手章节在正文点名新建 / 修改的文件，再 include 整文件，章尾链接示例目录。
2. 片段章节在 `z42` 块首写完整仓库路径注释，再 include 对应锚点：

````markdown
```z42
// examples/<part>/<chapter>/<file>.z42
{{#include ../../../../examples/<part>/<chapter>/<file>.z42:code}}
```
````

出处注释与 include 必须同指一个文件；同文件的后续片段也各自标注。
`console` 块由命令行说明执行对象，不额外加出处注释。
报错示例同时展示触发错误的源码；多个片段的输出按会话锚点拆分，不能把整程序输出贴给单个片段。

### include 与会话门禁

**本节只约束 learn。** z42 示例与可重放的终端命令 / 输出来自 `examples/`，由 `xtask test docs examples` 校验。

- `z42` / `console` 块正文只放一条 include；`z42` 块可在前面加上述出处注释（B6）。
- 不可运行示意用 `text`，必要时少量使用 `z42,ignore`；安装、curl、编辑器等无法在会话沙箱运行的命令用
  `sh` / `powershell`，示意输出用 `text`。
- 片段引用 `// ANCHOR: name` / `// ANCHOR_END: name`，不用行号（B2、B3）；有锚点的源文件不整文件 include（B4）。
- 页面只能 include `examples/<part>/<chapter>/` 下的内容（B5）；跨章节的独立示例各自维护。
- 章节目录与示例目录对应（B9）；每个工程至少被一个会话脚本覆盖（B8），每个脚本至少被一页 include（B7）。

```text
examples/<part>/<chapter>/
  <project>/
    z42.toml
    src/Main.z42
    run.console
  <scene>/<scene>.console
```

工程会话的沙箱是工程副本；演示 `z42 new` 等创建操作的会话放在空 scene 目录。
examples 只放手册配套内容，语言 / 库的覆盖写进测试；源码不加重复页面说明的「本文件演示了」头注释。

### 会话脚本与校验

脚本语法、沙箱、重放和 `--bless` 见[学习手册示例与会话脚本](../../internals/src/devinfra/learn-examples.md)。
尽量少用通配符，只匹配确实会变的部分；`--bless` 后人工审 diff，不能把不稳定输出直接固化。
