# 实现哲学与设计完整性

> 本文件管设计判断；授权、Scope 与暂停条件统一见 [workflow.md 越界防护](workflow.md#越界防护)。

## 实现方案原则（必须遵守）

**选择能完整解决当前问题、结构清楚且可维护的方案。** 先理解根因与约束，再实施；不以吞错、特例或临时兼容掩盖问题。
确需临时方案时说明原因与代价，取得 User 同意，并按[延后特性管理](#延后特性管理必须遵守)登记收尾条件。

### 不为破坏性顾虑而牺牲最佳方案

pre-1.0 内部重构可以调整 API、命名与文件位置，必要调用点同轮更新并验证。
调用点多不构成保留错误设计的理由；改变已确认行为仍受 workflow 的授权边界约束，
自举链变更还须遵守 [bootstrap-seed.md](bootstrap-seed.md)。

### 修复必须从根因出发

沿数据与调用链找到错误状态的来源，修正产生或传播错误的机制，并用回归用例证明问题被消除。
不要在所有消费端增加同名匹配、sentinel 推断或 catch 吞错；必须保留的防御检查应有明确契约与诊断。
跨阶段信息补齐时集中修正元数据，不让每个消费端各自猜测占位值。

### 系统性修复 vs Scope 控制

根因修复所需的文件、调用点与测试可补入本轮 Scope；新需求或未授权的行为 / 架构取舍按 workflow 裁决。
Scope 不允许处理的问题登记 Deferred，不在症状层留下假修复。

### 不为旧版本提供兼容

**pre-1.0 不为 z42 自身旧格式、API、IR 或命令面保留兼容路径。**
格式版本不匹配直接拒读；删除或改名时同步全部调用点，不留 alias、fallback 或长期双轨实现。

- wire 格式与指纹变化按 [version-bumping.md](version-bumping.md)执行。
- **种子过渡例外**：为上一代工具链启动所需的短期共存按 bootstrap-seed 执行；记录移除条件，到期删除。
- 操作系统接口、UTF-8 等外部标准按其契约实现，不属于 z42 旧版本兼容。

## 设计完整性原则（必须遵守）

通用机制需要堆特例、绕过封装、塞占位状态，或一个类型承担无关职责时，重新检查抽象与职责。
授权范围内的内部重构自主完成；需要 User 裁决时，说明当前设计、冲突点、可行选项、代价与推荐。
不得未经同意采用临时绕过，也不得借重构扩展已授权目标。

## 规范冲突检测（必须遵守）

**每条规则只保留一处权威定义，其他位置只留触发条件、摘要与链接。**

- 权威归属明确、含义未变：直接删除重复、修正失效引用，同步入口与索引。
- 当前 User 明确指令与仓库规范不符：在授权范围内以 User 指令为准，同步相关规范。
- 无法据授权与权威定义确定行为：列出冲突、选项和推荐，请 User 裁决；继续不依赖它的工作。

裁决结果同步所有相关引用。适用于 agent、工具入口及三本书。

## 事实校正责任（必须遵守）

User 的判断与可验证事实冲突时，主动给出代码、文档或验证依据与调整建议，不以「User 要求」为由实施已知错误。
User 决定方向，事实与约束应先说明；是否暂停依 workflow 的越界防护判断。

## 延后特性管理（必须遵守）

已决定暂不实现的具体缺口，登记在 `docs/internals/` 对应机制页的 `## Deferred`，并在
`docs/roadmap.md` 的 Deferred Backlog Index 加索引；只登记一处，不把整项内容复制到 roadmap。
抽象远期展望归 roadmap 或[语言特性决策台账](../../internals/src/features.md)。
页头摘要、当前限制与 Deferred 的分工见 [doc-system 防漂移](doc-system.md)。

```markdown
### <ID>: <标题>

- **来源**：PR / 机制页 / 实施发现
- **触发原因**：为什么暂不做
- **前置依赖**：解锁需要什么
- **触发条件**：什么时候回来处理
- **当前 workaround**（如有）：现阶段如何绕过
```

ID 保持稳定；设计期可用 `<feature>-future-<name>`，实施期可沿用 `D-N` 或 `<name>-residual`。
完成后删除对应缺口与索引，历史由 PR / git 承载。
