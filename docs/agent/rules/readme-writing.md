# README 写作规范

> 本文件管根 README 与目录 README 的结构。内容归属、链接、同步与当前状态规则见
> [doc-system.md](doc-system.md)；哪些目录必须有 README 见 [code-organization.md](code-organization.md)。

## 根 README

根 `README.md` 用英文介绍项目、提供最短上手路径，并按受众分流到文档。
按以下顺序组织，未适用的段整段省略，已有段名保持稳定：

| 段 | 内容 |
|---|---|
| 标题与定位 | 一句话介绍，说明当前迭代状态 |
| Why z42 | 能力与价值表；性能等硬指标给设计文档落点 |
| Quick Start | 最短可运行路径；完整步骤链接开发环境页 |
| Documentation | 「我想做什么 → 具体文档页」索引 |
| Repository Structure | 顶层目录与一句话职责 |
| License | 许可证 |

- 进度详情链接 roadmap；不另复制阶段表。能力要点放 Why z42，不再另设重复清单。
- Documentation 按用户（learn / reference）与开发者（internals / agent / roadmap）分流；一行一个意图。
- 不展开设计原理、完整命令面或内部文件职责表；段间使用 `---`，与现有风格一致。

**维护触发：**

| 改了什么 | 更新哪段 |
|---|---|
| 顶层能力 / 文档分区 | Why z42 / Documentation |
| 顶层目录 | Repository Structure |
| 上手涉及的命令 | Quick Start，并与开发环境页一致 |

## 目录 README

目录 README 用中文回答「做什么、入口在哪、怎么用、怎么测、深入读哪里」。
只列主干能力和关键文件，软限约 100 行；设计机制与权衡链接 internals，不复制正文。

### 六段模板（唯一 SoT）

**职责、功能索引、如何测试验证、关联文档**必备；有对外用法时写**基础用法**；**核心文件**建议写。
出现的段保持以下名称与顺序：

```markdown
# <目录名>

## 职责
[1–3 句：职责与边界]

## 功能索引
| 功能 | 入口 / 文件 |
|---|---|
| <能力> | <文件与符号> |

## 基础用法
[常用、可复制运行的命令或调用示例；完整契约链接参考手册]

## 如何测试验证
[可复制的测试命令与预期结果；禁止只写「跑相关测试」]

## 关联文档
- [对应机制页](<相对路径>)

## 核心文件
| 文件 | 职责 |
|---|---|
| <关键文件> | <一句话职责> |
```

- **功能索引按能力组织**，入口给文件与符号，不逐文件抄清单。
- **核心文件按文件组织**，不列生成物 / 临时文件；第 3 层 README 还要覆盖子目录职责。
- **关联文档指向当前机制与契约**；引入过程和历史 PR 通过 git / PR 追溯，不强制在 README 登记。
- review 时可沿「功能索引 → 验证命令 → 关联机制页」核对；是否更新 README 由维护触发判断。

### 按需补充

| 段 / 目录类型 | 写法与位置 |
|---|---|
| 待办 | 放在关联文档之后，只写与本目录有关的当前缺口；没有时省略，归属见 doc-system |
| 依赖关系 | 库 / 包目录可放在核心文件之后，说明依赖谁、用途与有无 interop |
| 库 / 包的功能索引 | 按公开类型、静态函数、常量分组；使用命名空间全名，读者能据此写 using |
| 库 / 包的核心文件 | 增加「类型」列，区分 class、static class、struct 等 |

README 不抄完整公开签名；stdlib API 详见生成的 reference，编译器内部符号按代码与 internals 查询。

### 维护触发

这是 [doc-system 三问](doc-system.md)中目录入口问题的细化，不要求每轮都改 README：

| 改了什么 | 更新哪段 |
|---|---|
| 文件结构、对外入口或能力变化 | 功能索引 / 核心文件 |
| 测试方式或命令 | 如何测试验证 |
| 用法或构建命令 | 基础用法 |
| 职责范围 | 职责 |
| 机制文档位置或依赖 | 关联文档 / 依赖关系 |

纯内部函数提取、变量改名等未影响上述入口时，不改 README。

## 行文纪律

只写上手、维护和 review 需要的重要信息，长尾细节交给代码与书；关键术语保留英文。
每节先给结论，代码引用用路径与符号，不写易过期的行号；当前状态与历史的分工以 doc-system 为准。
