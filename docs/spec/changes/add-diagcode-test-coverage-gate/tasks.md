## Why

规则 ⑧ 答的是「这个码**还活着**吗」。⑨ 答的是另一半：**「它活着这件事有人验过吗」**。

一个码可以有发射点、`error-codes.md` 写着 `✅`，而**全仓没有任何测试提到这个号** —— 于是它的
行为（报不报、报在哪、消息说什么）可以随下一次重构一起消失，而门全绿。

这正是 **E0407 当年反过来的那一半**：那次是「有测试、零发射」（测试在、发它的 pass 没了），
⑨ 盯的是「有发射、零测试」。

实测 main 上 **5 个**：`E0103` / `E0435` / `E0436` / `E0464` / `E0493`
（与结构审计独立清点的名单**完全一致**）。

## What Changes

**规则 ⑨**：每个活码必须被至少一处测试按码断言，否则必须在
`scripts/test/diag-untested-codes.txt` 里记账。**双向棘轮**（同 ④ 的形态）：

- 少一条 → 红（新加的活码没测试就想混过去）
- 多一条 → 红（某个码补上测试了，清单里那条就是假话）

⇒ 清单**只能缩短**。

「被断言」判据刻意宽（要答的是「有没有被任何一处钉住」，不是「钉得够不够好」）：码值或常量名
出现在**测试面**任一处即算。测试面 = `src/**/tests/**` ∪ `src/tests/**`（任意文本扩展名，含
`expected_build_error.txt` —— 跨包用例的断言就载在那里）∪ `examples/**`（`.console` 重放稿）
∪ `scripts/test/**` ∪ `docs/learn/**`。`src/` 那部分与 ②③ **同一趟遍历**（条件互补）。

## 🔴 两个坑，都是实测踩出来的

1. **注释里提到一个码不算钉住它。** 第一版没剥注释，于是 `E0493` 被算作已覆盖 —— 它在测试面里
   唯一的出现是 `xtask_test_targets.z42` 里一句**对比性注释**（「同 E0493 当年那条的形状」）；
   `E0436` 同理（三处全是注释，另一处还是断言 `ErrorCount == 0` 的**阴性**用例）。
   把注释算进来的门会报「覆盖了」，而那正是它要抓的东西。⇒ `.z42` 的测试面文本先剥行注释。
2. ⭐⭐ **本门自己的文件不算测试面 —— 否则棘轮自我擦除。** 允许清单住在 `scripts/test/` 下，
   而那正是覆盖面的一个根 ⇒ 清单里列的码因「出现在测试面」被判为已覆盖 ⇒ 下一次 `--update`
   把它们从清单里删掉 ⇒ 再跑又说未覆盖。**一个自指的门，两次运行给出互相矛盾的答案**
   （第一次报 {E0103,E0435,E0464}、第二次报 {E0436,E0493}）。`diag-literal-emitters.txt` 同病；
   **门脚本自身也同病** —— 它的诊断文本里逐字写着码号，算进覆盖面则「被它点名讨论过的码永远
   显得有测试」。判据按**文件名**而非路径前缀，将来搬家也不会悄悄失效。

> 这两条都属「门在量自己」那一族的空转形态 —— 正是本审计 R4 的主题，我在实现它的过程中
> 又亲手造了一次。
