# Proposal: L2 规则表 —— 把优先级数值与派发顺序变成数据

> 状态：🔵 DRAFT 待审批 ｜ 类型：lang（需规范先行）｜ 创建：2026-09-26
> 前史：本 change 是 `foreach-protocol-pluggable-syntax-program` 的**批 2**。
> 批 0（#783）、批 1（#841，`1bc0a3506`）已落地。D5 裁决（2026-09-23）：
> **keyword-led 与 ambiguous-lookahead 一起表化，顺序约束从注释变数据 + 守门。**

## Why

### 1. 优先级已经存在，但以九种不同形态散落在代码里

`syntax-customization.md:18` 说的「解析器是 Pratt 式优先级攀升（属实），但并非表驱动」
仍然准确。2026-09-26 重核 `ExprParser.z42` 的实况：

| 绑定力 | 构造 | 今天在哪 | 形态 |
|---|---|---|---|
| （最紧，无数值） | `.` / `()` / `[]` / 后置 `++`/`--` / 已废 `?.` | `:18,31,53,54,70` | 主循环里无条件 `continue`，**没有 bp** |
| 85 | 后缀 `switch` / `with` | `:77,108` | 内联守卫 `minBp <= 85` |
| 85 | 前缀 `-` `!` `~` `+` / 前置 `++`/`--` / 四种 cast | `_parsePrefix` `:342,349,359,371,385,408` | **硬编码 `_parseExpr(85)` 六处** |
| （无数值） | `名<T>(args)` 泛型调用回溯消歧 | `:116-146` | 必须先于二元 `<`，靠**位置**保证 |
| 60 | `is` / `as` | `:148,188` | 内联守卫 `minBp <= 60` |
| 25 | 已废 `??`（仍解析掉右侧） | `:198` | 内联守卫 `minBp <= 25` |
| 20 | 三元 `?:` | `:210` | 内联守卫 `minBp <= 20` |
| 10 | 赋值 / 8 个复合赋值 | `:219` + `_isAssignOp:784` | 内联守卫 + 独立谓词 |
| 30…80 | 11 个二元运算符 | `_infixBp:770-783` | **唯一像表的那一份**（if 链返回 int）|

外加三处**不在任何阶梯里的魔数**，它们编码的其实是「相对关系」而非数值：

- `:96` / `:99` switch arm 的 guard 与 body 用 `_parseExpr(11)` —— `11` 的含义是「赋值 bp 10 + 1」，
  即「排除赋值」。数值写死，关系不可见。
- `:852` lambda 体用 `_parseExpr(10)` —— 含赋值层（镜像 C#）。
- `PatternParser.z42:94` 模式常量用 `_parseExpr(45)` —— `45` 的含义是「高于 `|`(44)、低于 `^`(46)」，
  即「挡掉 or-模式的 `|`，但允许 `^`/`&`/算术」。**这条约束跨文件、靠两个无关文件里的数值差维持。**

⇒ 改任何一个数值时，没有任何东西会告诉你踩了别人的约束。

### 2. 语句派发已经收敛成一处，但「顺序」只有两条散注释在守

好消息（实测，与旧稿记载不同）：**语句关键字派发全仓只有一处** ——
`Parser.ParseStatement`（`Parser.z42:287-340`），`StmtParser.z42` 里没有第二条链。

坏消息是那一处的**顺序**承载了真实约束，而记录方式是注释：

| 顺序位 | 判别 | 顺序约束的记录方式 |
|---|---|---|
| `:309` | `_isDeconstructDeclStart()`（`{ X: x } = e;`）**先于**块语句 | ✅ `:307-308` 有带理由的注释 |
| `:334` | `_isLocalFnStart()` **先于** var-decl | ✅ 行尾一句 `// impl-local-fn-l2：先于 var-decl 判别` |
| `:335` | `_isVarDeclStart()` | — |
| `:336` | `_isDeconstructDeclStart()`（非 `{` 形态，第二次） | 🔴 **它排在 var-decl 之后这件事没有任何注释解释**。隐含约束是元组 var-decl `(T1,T2) name` 与元组解构 `(a,b) = e` 的消歧（靠 `)` 后是 Identifier 还是 `=`），理由散在 `StmtParser.z42:217-219,339-342,347-348` |
| `:337-339` | 兜底：**没有 `else`**，无条件落到 `_parseExpr(0)` | 语句位未知 token 的诊断因此来自表达式层（`:295-305` 的 `using`/`namespace` 拦截注释正是在吐槽这条级联）|

⭐ **这就是 D5「顺序约束从注释变数据」要解决的东西**，而它同时解锁了一件今天做不到的事：
**顺序是手写 if 链时，测试无法注入一个错误的顺序**；顺序变成数据后，单测可以拿着一张
**故意写反的顺序表**去跑同一批夹具，断言「反序会解析成另一种东西」——
这才是一道**会红**的顺序门（批 1 的教训：门的判别力来自夹具与可注入性，不来自判据措辞）。

### 3. 特性门只挂住了 2/15 个名字，而表是它唯一自然的挂点

批 1 让 `E0301` 首次发射，但只有 `control_flow`（if/while/for/foreach/do/switch）与
`exceptions`（try）真的关得掉东西 —— **其余 13 个名字仍是死旋钮**，这一点在
`LanguageFeatures.z42:11-16`、`z42-toml.md`、`syntax-customization.md` 三处都写明了。

原因是结构性的：`_requireFeature` 只能挂在「有一处集中派发」的地方，而批 1 时只有语句派发
是一处。`bitwise`（`|` `^` `&` `<<` `>>`）、`ternary`（`?:`）这类**运算符级**特性，
今天没有任何集中点可挂 —— 它们的判定散在 `_infixBp` 的 if 链与主循环的内联守卫里。
表建起来之后，`feature` 就是表项的一个字段（`syntax-customization.md:148` 的设计原话）。

`syntax-customization.md` 在 #841 里只在**文末**加了「✅ 批 1 已落地」的注记，
**页首状态与现状表没改** ⇒ 同一页里自相矛盾：

| `:10` 现状表 | 「存在但**零调用方**」 | 同上 |
| `:12` 现状表 | 「`[syntax]` 节**不存在**」 | 已存在（`ManifestLoader._parseSyntax`）|
| `:62` | 「`Phase1Profile()`（**21 个**特性全开）」 | **15 个**（#783 删了 6 个幻影）|

## What Changes

1. **表达式规则表**：把上面九种形态收敛成一张 `ParseTable` —— 每个 token kind 一条
   `{leftBp, ledKind(int tag), feature}`；主循环改为「查表 → 一个守卫 → 按 tag 派发」。
   三处魔数（`11` / `45` / 前缀 `85`）改为**从表里算出来的命名常量**，把「关系」变成代码。
2. **语句规则表**：`StmtRules` 每个引导关键字一条 `{stmtKind(int tag), feature}`；
   特性门改为**遍历表**（批 1 那段手写的 `If/While/For/…` 门列表随之消失 ⇒ 加语句时漏挂门这件事
   不再可能）。
3. **lookahead 顺序表**：四个探测位（`{`-解构 / local-fn / var-decl / 非`{`-解构）成为一张
   **有序**表，每项带「为什么在这个位置」的理由字段或原地注释；一道**注入错误顺序**的门。
4. **一致性守门**：表里出现的每个 `feature` 名必须在 `Phase1Profile()` 里（`Has` 已就绪）；
   判别力靠**注入一个假名必须红**来验。
5. **顺带让运算符级特性门变活**（范围见 D2-4）：本批的候选是 `bitwise` 与 `ternary` ——
   它们在表里是天然表项，且各有一条好写的负例门。
6. **文档订正**：`syntax-customization.md` 的页首状态 / 现状表 / 特性数 / `:197` 一致性检查一节，
   按落地实况重写（第 4 节那张表逐行）。

## Non-goals

- **不改任何优先级数值**（这是收敛不是改语义）⇒ **字节必须不变**，靠自举不动点 + 25 包 zpkg 对账守。
- **不做第 3 层用户定义语法**（`operator` / `keyword` 声明、运行时插表）——roadmap Deferred 不动。
- **不做 `using` 语句**——批 3/4。
- **不补 `<<=` / `>>=`**：`operators.md:117` 明写「不支持，写了是语法错误」，词法器也没有这两个
  token ⇒ 已记账的**有意缺口**，不是缺陷，本批不动它（但表会让这个缺口第一次可见）。
- **不动已废运算符的解析**（`?.` / `??` 仍按原 bp 解析掉右侧再报 E0480 —— 那是刻意的防级联手法）。
- **不让其余 11 个死旋钮变活**：每个都需要自己的负例门，攤进本批会让「字节不变」这条对不上账。
- **不碰后端 / 不 bump 格式**。
