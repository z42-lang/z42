## Why

`xtask test diagcodes` 的七条规则盯的全是**码这个对象**——谁占了号、谁发射它、欠账多久、
散文有没有乱说形态。**没有一条盯「它还活着吗」**：

- ②③ 只管「发出去的 / 引用到的」必须在登记表里，**反方向不管**；
- ④ 只管字面量站点清单；
- ⑤ 只比码号集合。

于是 **E0407 那一形**——常量在、`error-codes.md` 写着 `✅`、而发它的 pass 随老 C# 编译器一起
没了（528 行的 `FlowAnalyzer.cs` 整个丢掉）——能一路绿到有人手工 grep 才发现。

更麻烦的是 ⑤ 留下的盲区：**「刻意保留 / 退役」与「已经腐坏」长得一模一样**（都是「登记表里有、
零发射点」），⑤ 甚至**要求**零发射常量存在 ⇒ 机器无法分辨。

## What Changes

新增**规则 ⑧**：登记表里每个码的「实际有没有发射面」必须与 `error-codes.md` 状态列一致。

- 有发射面却标着 `⚠️ 零发射点` / `❌ 已退役` → 红（号被复活，或文档腐了）
- 零发射面却没这么标 → 红（**这就是 E0407 那道门**）

**不新增一份真相**：那一列本来就记着每个码的状态，只是此前由**人工 grep** 产生、零机器校验
（`error-codes.md` 的「这张表怎么来的」自己写着做法就是 grep）。⑧ 把已有的人工列变成对账，
维护成本为零。

判据细节：

- 「有发射面」= 非 `tests/` 源里的**字面量发码**（④ 那批站点）∪ **`DiagnosticCodes.<Name>` 引用**。
  ⚠️ **测试里断言一个码不算它活着** —— 那恰恰是 E0407 当年「有测试、零发射」的形状。
- 「文档声明为死」= 只看**表格行**且**第一列提到该码**的那些行里含 `零发射点` / `已退役`。
  只看第一列是必要的：状态/描述列里提到别的码是常事（「见 E0466 一节」），拿整行去抽会把
  无关的码一起判死。`E0901 / E0902` 那种一行两码也落在第一列。
- 汇总行打出**账面**（活 / 零发射各几个）——「这两个数就是有多少条保护真的在跑」。

  以及一份「测试面」的扫描范围定义（`src/**/tests/` ∪ `src/tests/` ∪ `examples/` ∪
  `scripts/test/` ∪ `docs/learn/`），单独一刀。
- **不去接线那 28 个零发射码**。它们各自是独立的语义缺口（`E0403` 缺 return 不报、

  属功能而非门禁。⑧ 的作用是把这笔债变成**机器可见且不会悄悄增长**的。
