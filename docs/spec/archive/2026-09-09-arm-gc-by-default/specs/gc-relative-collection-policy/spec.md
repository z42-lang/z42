# Spec: 相对量的自动回收策略

## MODIFIED Requirements

### Requirement: 自动回收不再需要预算

自动回收的触发条件全部是相对量，因此在未设置 `Z42_GC_MAX_BYTES` 时同样生效。
`Z42_GC_MAX_BYTES` 是**软上限**：设置后压缩回收余量并提供额外的近上限触发。

#### Scenario: 未设预算的堆仍然回收

- **GIVEN** 未设置 `Z42_GC_MAX_BYTES`
- **WHEN** 堆持续分配并越过增长闸门
- **THEN** 发生自动回收

#### Scenario: 不再增长的堆不回收

- **GIVEN** 一个已经停止分配的堆
- **THEN** 不再发生自动回收，无论经过多久

#### Scenario: 活集超过软上限时回收次数有界

- **GIVEN** 一个活集持续增长并超过软上限的堆
- **WHEN** 它继续分配
- **THEN** 回收次数保持有界，而不是每个闸门都收一次

### Requirement: 回收余量按活集的比例计算

一次 major 之后允许老年代吃进的字节数为「上次 major 后活集的一个固定比例」，
下界为若干个 nursery。软上限存在时，余量不得让「活集 + 余量」越过上限，
但仍以下界兜底。

#### Scenario: 活集越大，余量越大

- **WHEN** 两个堆的活集相差数倍
- **THEN** 较大者的回收余量按比例更大

#### Scenario: 活集极小时余量不塌陷

- **GIVEN** 活集接近于零
- **THEN** 余量仍不小于下界（若干个 nursery）

### Requirement: 两种模式的闸门不同

分代模式下 minor 的闸门是一个 nursery 的分配量；非分代模式只有一代，
每次回收都是全量的，闸门是一个完整的余量。

#### Scenario: 同一负载下分代回收得更频繁

- **WHEN** 同一分配负载分别在分代与非分代模式下运行
- **THEN** 分代模式的回收次数更多，且两者都大于零

## ADDED Requirements

### Requirement: 分配路径上的触发判断必须是无锁的

分配路径判断「是否需要咨询回收策略」时不得获取堆的互斥锁；策略本身（需要锁）
每个增长闸门至多进入一次。

#### Scenario: 策略在一次闸门内至多被咨询一次

- **WHEN** 策略被咨询后决定不回收
- **THEN** 下一次咨询要等到再分配一个闸门之后

#### Scenario: 回收之后按新的活集重新装填

- **WHEN** 一次回收结束
- **THEN** 下一个触发点按回收后的活集重新计算
