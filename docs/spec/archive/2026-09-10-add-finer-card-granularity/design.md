# Design: 32 张卡 + 扫过即清

## Architecture

```
   card_dirty[ci] : u32     ← 一直就是 u32，只用了 bit 0
   ┌─┬─┬─┬─┬ ... ┬─┐
   │0│1│2│3│     │31│        32 张卡 × 每张 8 条 = CHUNK_SIZE(256)
   └─┴─┴─┴─┴ ... ┴─┘
        ▲
     card_of(entry_idx) = entry_idx / ENTRIES_PER_CARD

   minor 播种：对每张脏卡的每条活条目
       ├─ 年轻 → 当根推进队列（不变）
       └─ 老   → 直接追踪，把年轻孩子入队
       并记录「这张卡是否还够到年轻的东西」
   扫完 → 够不到的卡就地清掉
```

## Decisions

### Decision 1: 32 张卡是**免费**的

`card_dirty` 一直是 `Vec<u32>`，却**只用 bit 0**。`CHUNK_SIZE` 是 256，
`256 / 32 = 8` 正好整除 —— 于是 32 张卡、每张 8 条，**一个字节的额外内存都不要**。

这是本仓第二次在「已经付过钱的空间」里找到位置：#552 是块头 `align(8)` 的 4 字节
padding，这次是从没用过的 31 个位。**先问「现有字段还有空位吗」，往往比加字段快也便宜。**

### Decision 2: 扫过即清 —— 卡是提示，不是事实

一张卡的含义是「这里**可能**有跨代边」。扫过一次发现没有，它就不该继续当根。
在这之前**没有任何东西在 major 之前清卡**，而写屏障**和晋升**（#539 加的
`dirty_cards_for_newly_old_*`）都在往里加 —— 脏集因此单调滚大到活堆的约 65%。

清掉是安全的，因为破坏「老条目指着年轻的 ⇒ 卡是脏的」这条不变量只有三条路，
三条都有人负责（见 book 的卡表不变量一节）：**写**（写屏障）、**晋升**
（`dirty_cards_for_newly_old_*`，与本次清扫在同一个 STW 窗口里、在它之后跑）、
**major 清卡**（`rebuild_card_table`）。

### Decision 3（⚠️ 试过并**放弃**）: 不把年轻的脏卡条目当根

播种时把年轻条目也当根，是 chunk 粒度时代的产物：一次跨代写就让整块 256 条
——**包括其中的年轻对象**——全部存活。按理说「脏卡里的年轻对象」并不是根。
把它去掉试了一版：

| gen，8M nursery | 中位停顿 | 峰值 RSS |
|---|---|---|
| 基线 | 26.8 ms | 581.2 MB |
| 本 change | 18.3 ms (**−32%**) | 617.9 MB (**+6.3%**) |
| + 不把年轻条目当根 | 18.2 ms | 617.7 MB |

—— 停顿没再多赚，RSS 也没变。真正让小 nursery 档 RSS 涨 6% 的**不是**它。
对照实验（保留旧播种方式、只改粒度与清扫）拿到 24.5 ms / 572.2 MB，
而它与本 change 的 **`gc_reclaimed_bytes` 逐字节相同**（449 084 216）——
**两版回收的是同一批对象**，差别只在标记顺序如何影响后续的槽位复用与整块回收，
也就是**分配局部性**，不是保留策略。

结论：**去掉年轻根是一次语义改动**（改的是「收什么」），本 change 不做，
留给单独立项 —— 它在默认 nursery 下没有可测收益，只在小 nursery 档有争议。

### Decision 4: 老条目在播种处直接穿透

`fix-minor-stale-mark-on-old-roots`（#537）之后，BFS 对一个老条目本来就只做
「不标记、追踪、把年轻孩子入队」。把它挪到播种处，省掉一次 push + 一次 pop，
**并且让「这张卡还够不够得到年轻的东西」这个判断有地方可放**——不然卡的归属在
BFS 里已经丢了。

## Implementation Notes

- `iterate_dirty_cards` 用 `bits.trailing_zeros()` + `bits &= bits - 1` 逐张卡走，
  只碰点亮的那些；回调多一个卡号参数供清扫用。
- 卡的清扫用一个**单槽累加器**：`iterate_dirty_cards` 保证一张卡的条目是连续走完的，
  所以不需要 map，换卡时结算上一张即可。
- `is_card_dirty(ci)` 的语义从「bit 0」变成「整字非零」= 这个 chunk 有任何脏卡。

## Testing Strategy

- `a_write_dirties_only_its_own_card` —— 点亮一条，只有它那张卡的 8 条成为根
  （**32× 收窄就是本 change 的全部意义**）
- `clean_card_clears_only_that_card` —— 清一张不动同一个 `u32` 里的其它张
- 既有的卡测试跟随新签名；`iterate_dirty_cards_yields_all_entries_in_the_dirty_card`
  改成把 32 张卡全点亮（那才是旧的 `mark_card_dirty(0)` 的含义）
- 三个跨代正确性测试（#537 / #539 留下的：`old_root_traces_its_young_children_at_every_minor`
  / `promoted_owner_keeps_the_young_child_it_was_holding` /
  `major_rebuilds_cards_for_surviving_cross_gen_edges`）原样通过 ——
  它们正是「卡清早了会丢对象」的守卫

## 实测（同一 seed、同一次会话）

| 配置 | 周期 | 中位停顿 | 最大停顿 | 峰值 RSS |
|---|---|---|---|---|
| **gen 默认（前→后）** | 10 | 31.2 → **22.2 ms (−29%)** | 89.3 → 80.9 ms (−9%) | 763.9 → 765.6 MB (+0.2%) |
| gen 8M（前→后） | 61 | 26.8 → **18.3 ms (−32%)** | 74.6 → 75.6 ms | 581.2 → 617.9 MB (+6.3%) |
| gen 4M（前→后） | 102 | 24.1 → **18.1 ms (−26%)** | 80.5 → 71.2 ms | 576.7 → 624.3 MB (+8.3%) |
| **stw 默认（前→后）** | 4 | 57.9 → 57.9 ms | 86.4 → 90.1 ms | 748.1 MB **不变** |

**STW 一分不动是应该的** —— 它没有代，不用卡表。这也是这一版改动作用面的证明。

⚠️ **小 nursery 档 +6~8% RSS**：见决策 3 —— 回收的对象逐字节相同，差别是标记顺序
带来的分配局部性。默认 nursery 下 RSS 持平（+0.2%）。

## 还剩什么

1. **`purge_blocks` 的 retain 7–10 ms** —— 每元素已是 O(1) 判定，但要摸 270 万个块头
   （随机读）。要把 `all_blocks` 改成按 chunk 分桶，回收一个 chunk 就是 `clear()`。
2. **「不把年轻的脏卡条目当根」** —— 见决策 3，语义改动，需单独立项 + 单独证据。
3. **翻 `Z42_GC_MODE` 默认**：分代中位停顿现在是 **22.2 ms vs STW 57.9 ms（−62%）**，
   代价 RSS +2.3%。前置仍是补 CI 的分代覆盖。
