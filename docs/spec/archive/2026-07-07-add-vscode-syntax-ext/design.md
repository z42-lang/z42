# Design: VSCode 语法高亮扩展（生成器驱动）

## Architecture

```
Lexer.z42 _initKeywords()            ← 关键字唯一 SoT（≈90 项）
        │  KeywordCount()/KeywordNameAt(i) 只读访问器
        ▼
z42c --dump-keywords                 ← 每行一个，源顺序，exit 0
        │  (xtask fork in-tree z42c；warm 由 build wave 保证，cold 走 _ensureSeed)
        ▼
xtask 生成器 (xtask_install_vscode.z42)
  ├─ 分类表（control/declaration/modifier/type/literal…，住生成器脚本）
  ├─ 穷尽校验：dump ∖ 分类 ≠ ∅ → 报错指名；分类 ∖ dump ≠ ∅ → 报错（幽灵关键字）
  └─ 模板渲染：z42.tmLanguage.tpl.json 的 __KW_<GROUP>__ → \b(kw1|kw2|…)\b
        ▼
syntaxes/z42.tmLanguage.json         ← 生成产物，入库
        │
  xtask deps install vscode          → 装全部 VSCode 资产（当前唯一项 = 语法扩展：
                                       重生成 + symlink ~/.vscode/extensions/z42.z42-lang）
  xtask test vscode-syntax           → in-process 调生成器检查函数（重生成到内存与入库
                                       文件 diff），挂 _testAll 链尾，GREEN gate 防漂移；
                                       亦是手动漂移检查入口（install 不留 --check flag）
```

## Decisions

### Decision 1: 扩展位置 = `src/toolchain/devtools/vscode/`

**问题：** 扩展是编辑器资产包，不是 `z42d` CLI 子命令，放哪。
**选项：** A — devtools 下与 `core/` 并列；B — 仓库根新顶层目录 `editors/`。
**决定：** 选 A。职责上属开发体验工具归 devtools；B 期 LSP client 也长在此处，
与将来 `z42d lsp` server 前后端就近。不新增顶层目录。

### Decision 2: SoT 走生成器而非「手工 + diff 检查」

**问题：** grammar 关键字表与 Lexer 必然双份。
**决定：** User 裁决（2026-07-07）：生成器；关键字由 z42c 导出，`xtask install` 调用。
导出动词顺 z42c.driver 既有 `--dump-tokens/--dump-ast` dump 族模式，逻辑住
`z42c.syntax/DumpTool`（Main.z42 已 475 行、逼近 500 硬限，只加分发行；若实施中
超硬限，停下——拆分是独立 refactor change，不混入本变更）。

### Decision 3: 分类表住生成器脚本，穷尽性机械校验

**问题：** 高亮分组（控制流/声明/修饰符/类型/字面量）是表现层概念，Lexer 里没有。
**选项：** A — 分类表写进生成器脚本（z42 数组）；B — 独立数据文件；C — 塞进 Lexer。
**决定：** 选 A。分组纯属扩展表现层，不污染编译器；防漂移不靠「分类表也是 SoT」，
靠**穷尽校验**：dump 出的每个关键字必须恰好落在一个分组，多、漏、重都直接报错。
新关键字进 Lexer → gate 红 → 开发者被迫补分类并重生成，闭环。

### Decision 4: 生成产物入库 + `--check` 挂 GREEN gate

**问题：** `z42.tmLanguage.json` 只在 install 时生成，还是入库？
**决定：** 入库。理由：手动安装/代码审阅可用、无 z42c 也能用扩展；漂移风险由
`--check` 兜住。gate 挂接：`_testAll` 链尾新增轻量 stage `vscode-syntax`
（`packages-config` 类自检 stage 先例，但那些不在 all 链内；本 stage **进 all 链**，
因为它守的是跨子系统 SoT 一致性，性质同自举不动点）。成本≈一次 z42c fork，可忽略。

### Decision 5: 安装 = symlink，MVP 仅 macOS/Linux

**问题：** 扩展如何进 VSCode。
**选项：** A — symlink 到 `~/.vscode/extensions/`；B — copy；C — vsix 打包。
**决定：** 选 A（目录名 `z42.z42-lang`；`ln -sfn` 语义，重复安装幂等）。symlink 使
repo 内 grammar 改动即时生效（重载窗口即可），适合快速迭代期。Windows symlink 需
特权，MVP 检测 win32 后打印手动 copy 指引并 exit 1；自动化留 deferred。
C 需 node/vsce，违背零依赖目标，发行期再议。

### Decision 6: 命令面 = `xtask deps install vscode`（deps 聚合 component，非独立命令）

**问题：** 命令面几经修订：`install vscode-ext`（只装本扩展）→ `install vscode`
（顶层聚合）→ 最终并入 deps。
**决定：** User 裁决（2026-07-07 二次修订）：`deps install vscode`——收敛后的
`deps install` 上的 optional positional component（**依赖 `simplify-xtask-deps`
先落地**，见其 design Decision 6）。在 deps 两层依赖模型（平台必备直装 / 用到才装）
之外，vscode 资产属第三类：**主机集成，用户显式触发**（编辑器集成无法"用到自动装"）。
实现形态：`xtask_install_vscode.z42` 内部按「资产项」组织（每项 = 生成步骤（可空）+
安装步骤 + 检查步骤），主流程顺序遍历逐项执行；本变更登记第一项 `syntax-ext`，
后续 VSCode 依赖扩展（B 期 LSP client、snippets、调试扩展等）注册新项即可。
漂移检查不走 install 的 mode flag（deps 收敛已删全部 mode flag），由
`xtask test vscode-syntax` stage in-process 调检查函数承担。

### Decision 7: grammar 覆盖面严格对照 Lexer 现状

规则全量（模板手写部分）：
- 注释：`//`、`/* */`（不嵌套）
- 字符串：`"…"`（`\` 转义）、raw `"""…"""`、插值 `$"…{expr}…"`（洞内嵌套高亮）、字符 `'…'`
- 数字：十进制 / `0x` / `0b`、`_` 分隔、小数、指数 `[eE][+-]?`、后缀 `L u f d m`
- 属性：`#[…]`
- 运算符全集（含 `?.` `??` `=>` `->` `::` `..`）
- 约定式着色：PascalCase 标识符 → 类型 scope；`ident(` → 函数调用 scope
- 关键字五组（占位符注入）：control / declaration / modifier / type / literal

scope 命名遵循 TextMate 惯例（`source.z42`、`comment.line.double-slash.z42`、
`string.quoted.double.z42`、`keyword.control.z42`、`storage.type.z42`、
`constant.numeric.z42`…），保证主流主题开箱着色。

## Implementation Notes

- **自举种子约束**：z42c 侧与 xtask 侧均只用现有语法 + 已发布 stdlib API（新代码
  沿用既有写法），无 support/use 分期问题；xtask 新脚本被 `[sources] include = "**/*.z42"`
  glob 自动收录，免改清单。
- **z42c 调用方式**：xtask fork in-tree z42c（`_exec` 既有设施）；`deps install vscode`
  前置确保编译器已建（复用 build compiler 的 warm/cold 路径）。
- **Main.z42 分发**：`--dump-keywords` 无 file 参数，须在 `argv.Length < 2` usage
  守卫**之前**分发（现有守卫要求 ≥2 参）。
- **生成确定性**：关键字按 dump 源顺序（= `_initKeywords` 注册序）注入，正则拼接
  无任何哈希/文件系统迭代——同输入必同字节（common-pitfalls §1 天然满足）。
- **生成文件头**：注入 `// GENERATED by xtask deps install vscode — DO NOT EDIT`
  头注释（JSON 用 `"__generated__"` 键承载），审阅者可辨。

## Testing Strategy

- 单元测试：`lexer_tests.z42` 新增——`KeywordCount() > 0`、访问器逐项与
  `_kwLookup` 行为一致（哨兵关键字 `fn`/`params` 命中）、`DumpKeywords()` 行数 ==
  `KeywordCount()`。
- 自检 stage：`xtask test vscode-syntax` = in-process 调生成器检查函数（穷尽校验 +
  字节 diff），挂 `_testAll` 链尾；本变更即其回归测试（新 CLI 命令 + 生成器均被覆盖）。
- 视觉验收：用 `examples/*.z42` 打开逐项核对高亮清单（注释两形态/字符串四形态/
  数字全形态/关键字五组/属性/运算符），记录进 tasks.md 备注。
- VM 验证：runtime 零改动；GREEN 照常全 stage（`xtask test`，含新 stage）。
