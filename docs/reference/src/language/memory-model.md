# 所有权与内存模型

**z42 没有所有权、借用、生命周期。内存由 GC 管，你不需要写 `clone()`、`&`、`&mut`、`'a`。**

写 z42 时关于内存只有一件事要搞清楚：**赋值的时候，复制的是值还是引用。**

## 没有所有权

z42 始终带 GC，这是一条固定决策，不会改：

- 不需要标注生命周期，不会有借用检查器报错。
- 一个对象可以被任意多个变量同时引用，最后一个引用消失后由 GC 回收。
- 代价是 GC 停顿。调优旋钮见[运行时设置](../toolchain/README.md)。

## 值类型与引用类型

| 类型 | 语义 | 赋值 / 传参 / 存进容器时 |
|---|---|---|
| `int` `long` `float` `double` `bool` `char` 等基本类型 | 值 | 复制值 |
| `string` | 引用，但**不可变** | 复制引用；因为改不了，观察不到与值语义的区别 |
| `struct` | 值 | **逐字段复制**（⚠️ 见下方「已知偏差」） |
| `enum` | 值 | 复制值 |
| 元组 `(int, string)` | 值 | 底层是合成的值元组，按值复制 |
| `class` | 引用 | 复制引用——**两个名字指向同一个对象** |
| 数组 `T[]` | 引用 | 复制引用 |
| 接口类型 | 引用 | 复制引用 |
| 委托 / lambda | 引用 | 复制引用 |

```z42
class C { public int x; }
struct S { public int x; public int y; }

var c1 = new C(); c1.x = 1;
var c2 = c1;      // 复制引用
c2.x = 99;        // c1.x 也变成 99 —— 同一个对象

var s1 = new S(1, 2);
var s2 = s1;      // 逐字段复制
s2.x = 99;        // s1.x 仍是 1 —— 两份独立的值
```

数组是引用类型，但**数组元素**按元素类型的语义走：`S[]` 里存的是一份份独立的 `S` 值，
`var e = arr[0]` 拿到的是副本，改 `e` 不会写回 `arr[0]`。

## 复制发生在哪里

对值类型，下面每一处都会产生一次复制：

- 赋值给另一个变量：`var b = a;`
- 传给方法（没有 `ref` / `out` / `in` 修饰时）
- 从方法返回
- 存进数组、字段或其它容器
- `foreach` 每一轮拿到的循环变量

对引用类型，上面每一处复制的都是引用，指向的对象只有一个。

## ref / out / in：按引用传参

在参数和调用点同时写修饰符，方法就能改到调用方的变量：

```z42
void Increment(ref int x) { x = x + 1; }

var c = 0;
Increment(ref c);     // c 变成 1
```

三个修饰符的**设计意图**是：

| 修饰符 | 意图 |
|---|---|
| `ref` | 双向：调用前必须已赋值，方法可读可写 |
| `out` | 只出：方法必须在返回前赋值，调用前不必初始化 |
| `in` | 只入：按引用传（避免复制大 struct），方法不得修改 |

`out` 支持在调用点内联声明变量：

```z42
if (TryParse("42", out var n)) { /* 这里能用 n */ }
```

`params` 不能与 `ref` / `out` 或默认值同时使用（`ParamsModifierConflict`）。

> ### ⚠️ 当前实现尚未强制这三者的区别
>
> **`ref`、`out`、`in` 目前在编译器里塌缩成同一个标志，行为完全等同于 `ref`**，
> 上表的「意图」还没有对应的检查。实测（2026-09-17）：
>
> | 写法 | 应当 | 实际 |
> |---|---|---|
> | `void M(in int x) { x = 99; }` | 编译报错（`in` 只读） | 编译通过，调用方的变量被改成 99 |
> | `bool M(out int v) { return false; }`（从不赋值 `v`） | 编译报错（`out` 必须赋值） | 编译通过；调用方读 `v` 时抛 `got Null` |
> | `void Inc(ref int x)` 却调用成 `Inc(v)`（漏写 `ref`） | 编译报错 | 编译通过，**写入静默丢失** |
>
> 最后一条最容易咬人：漏写 `ref` 不报错，方法里的修改直接丢掉。
> **在这些检查补上之前，调用点请自己写全修饰符。**

## 装箱

把 `struct` 或基本类型赋给 `object` 或接口类型时会**装箱**——值被复制到一份堆对象里。
装箱后的那份有自己的引用身份，改原值不影响它。详见[装箱](boxing.md)。

## 什么时候真的需要关心

大多数代码不需要。下面三种情况要留意：

- **大 struct 频繁传参**——每次传参都是一次逐字段复制。
- **以为改的是原件，其实改的是副本**（或反过来）——上面 `class` / `struct` 的例子就是这个坑。
- **循环里意外装箱**——把值类型塞进 `object[]` 或接口变量，每次都会分配堆对象。

> ### ⚠️ 已知偏差：单字段 struct 仍是引用语义
>
> 值语义只对**多字段** struct 生效。**只有一个字段的 struct 目前表现为引用语义**：
>
> ```z42
> struct One { public int x; public One(int x) { this.x = x; } }
> var a = new One(1);
> var b = a;
> b.x = 99;        // a.x 也变成 99 —— 与上表描述不符
> ```
>
> 两个及以上字段的 struct（局部变量、数组元素）值语义正确。这是实现缺口，不是设计意图。

## 与 C# / Rust 对照

| | z42 | C# | Rust |
|---|---|---|---|
| 内存回收 | GC | GC | 所有权 + 作用域 |
| 所有权 / 借用 / 生命周期 | 无 | 无 | 有 |
| `class` | 引用类型 | 引用类型 | —— |
| `struct` | 值类型 | 值类型 | 值类型（`Copy` / `Clone` 另说） |
| 按引用传参 | `ref` / `out` / `in`（检查未落地） | `ref` / `out` / `in` | `&` / `&mut` |
