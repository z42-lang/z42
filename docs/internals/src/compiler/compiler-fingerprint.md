# 编译器缓存身份

增量编译把编译器身份和格式版本一起写入每文件的 `.meta` 与整包的 `package.meta`。不同版本的
编译器可能对同一份源码发出不同字节码或诊断，因此即使格式版本相同，旧缓存也需要失效。
依赖签名缓存使用同一个身份来校验其归一化结果。

## 身份来源

`CompilerFingerprint.Value()` 在进程内复用加载器计算出的内容身份。加载器从实际解码的入口包
开始，沿包的依赖清单建立闭包。已载入的依赖使用解码时取得的摘要。惰性依赖使用加载器选定的
路径或其文件名搜索顺序读取内容。摘要包含入口包、依赖文件名和包内容，路径变动本身无需使
缓存失效。构建期间应使用内容稳定的一套 SDK。

旧运行时或无法确定完整包闭包的运行环境使用本次会话的身份。有熵源时该身份只允许进程内
复用缓存。缺少熵源时跳过持久缓存读取。升级后原有手工条目的缓存身份会自然失配。

格式版本仍校验 zbc 与 zpkg 的兼容性。编译器修改不需要登记缓存条目。
